## Implemented

- **C07, contract configuration/state:** supplied balances and collateral-enabled flags are separate. HF/LTV exclude disabled collateral while its balance remains withdrawable. Added active/paused/frozen gates, supply/borrow caps, borrowing and flash-loan permission, eMode collateral/borrowing membership and category prices, isolation debt-ceiling counters, automatic isolated-collateral supplier permissions, siloed borrowing, zero-LTV withdrawal/transfer restrictions, and oracle-sentinel gates. Explicit collateral/eMode actions are supported. Governance changes can be supplied as dated evidence; state-query copies and transaction paths use that evidence.
- **C04–C05:** explicit V3.3 close-factor, $2,000 selected-position thresholds, $1,000 residual checks, and deficit accounting, alongside pre-3.3 rules. Added `receiveAToken`, eMode liquidation bonuses, treasury fee ownership and underlying-liquidity checks. Configured protocol version must match liquidation rules. Dated input can provide version/bonus/fee automatically; unknown versions are rejected. No automatic assignment of an upgrade activation date.
- **C08:** reserve indices now use integer RAY `MathUtils` order and rounding, including the integer-truncated compounded-interest terms. Added separate account stable debt with its own principal/rate/timestamp, pre-3.2 stable borrow/repay/rate swaps/rebalance gates, mixed-debt liquidation burning variable debt first, and explicit rejection of missing stable-rate evidence. Added treasury claims for the variable-interest reserve-factor share. Full repayment removes machine-rounding residue only within a bounded ULP/token-quantum tolerance; larger aggregate debt underflow is an error. Rewinding an accrued reserve is prohibited.
- **C10:** a chain/address asset registry and explicit profile conversion interface preserve underlying identity. Both native and bridged USDC remain distinct; an ambiguous `USDC` symbol is rejected. Polygon's previously unknown `0x6533afac2e7bccb20dca161449a13a32d391fb00` market is verified as **aJEUR**, underlying `0x4e3decbb3645551b8a19f0ea1678079fcb33fb4c`, 18 decimals. The parent checkpoint adapter loads that verified mapping without changing old caches. New profile generation retains market/asset, payer/beneficiary and rate-mode metadata when present.
- **C11:** optional dated index evidence accrues snapshots using **target index / snapshot index**, never by multiplying raw balances by the index a second time. Missing intervals or unknown stable/variable debt modes fail explicitly. Explicit initial positions can be loaded without double-counting their balances in supplied global reserve totals. Snapshot-only fallback remains visibly stale; supplying index evidence does not certify independent chain truth.
- **C12–C13:** explicit aToken transfers, complete transaction bundles and flash-loan callbacks; atomic rollback includes reserve accrual and all constituent actions. Flash principal is credited once, repayments/premiums are required, debt-opening modes are separate, and overlapping settlement Borrow logs are rejected unless explicitly identified as callback actions. Payer, on-behalf-of borrower/beneficiary and withdrawal recipient have separate accounting. Credit delegation requires explicit evidence. Public protocol actions also revert on failure. A dedicated pre-3.3 observed-liquidation path applies verified past receipt legs without inventing an external liquidator wallet; it rejects the current/future event relative to an explicit intervention/evaluation cutoff. Self-liquidation and post-3.2 deficit receipts require the fuller execution path.
- **C06/C14:** dated configuration, protocol-version, index and oracle evidence interfaces reject missing/expired coverage. Same-block evidence can be bounded before a transaction's log. Result metadata records source coverage, execution order, applied supplementary actions and failures; a missing-history case is no longer labelled a complete reconstruction merely because actions did not throw. `require_verified_history` enforces the declared input-coverage requirements. Registry bytes participate in the parent simulation cache identity. Fixed the simulation CLI's profile-file loading.

## What is still not established

**This is not a claim that all historical-fidelity concerns are closed.** The software can consume substantially more complete evidence, but the currently downloaded data do not supply it:

1. Full Polygon upgrade activation blocks and dated reserve/eMode/isolation/sentinel settings across the research window are still absent. V3.4 and later rules are not implemented. Governance confirmation of an upgrade date is not an exact deployment boundary.
2. The existing indexed snapshots do not carry historical collateral flags or distinguish stable/variable borrower state. They also lack complete intervening rate and oracle histories. Do not enrich old rows with present-day nested objects. `AAVE_HISTORICAL_EVIDENCE` is optional evidence input, not a claim that such a file was collected.
3. Standalone indexed flash-loan logs do not contain the callback, premiums, credit delegation and all wallet transfers. They cannot be turned into a complete bundle just by setting a flag. Active legacy recommendation profiles therefore do not automatically consume all downloaded transfers/flash loans. Overlapping events still require receipt-level reconciliation.
4. Existing symbol-aggregated wallets/profiles cannot be unambiguously split into native/bridged USDC from the symbol alone. The registry/CLI rejects ambiguity; regeneration from address-bearing source rows and explicit funding remains necessary. Survival/model task labels were not changed.
5. RAY index arithmetic is integer-based, but the legacy token-unit balance/price interface still uses floats. Full wei-level EVM equivalence is **not** claimed. Stable-debt aggregate rates, treasury accrual and full-pool background changes need complete market-state evidence; individual-account replay with synthetic pool liquidity is still an approximation. Solidity differential execution and complete historical state validation remain to be done.

Strict event-label counts remain TP=41, FP=46, TN=5,858, FN=206; precision 47.13%, recall 16.60%. **No historical detection improvement is demonstrated.** These are comparisons against observed execution labels; an eligible position without a liquidation transaction is not independently proven to be a false eligibility flag. These expose missing state/invalid replay actions; they are not evidence that an on-chain repayment failed. ## Commands and use

From `Aave-Simulator`:

```bash
MPLCONFIGDIR=/tmp/aave-contract-mpl python -m unittest discover -s tests -q
python -m tools.prepare_contract_profile --input profile.json --output profile-addresses.json
python -m tools.run_single_simulation profile.json simulation-output.log
```

The conversion command requires an unambiguous address/market identity for ambiguous symbols, including wallets. It does not fabricate address-specific price or configuration histories. An address-keyed profile must also supply matching `reserve_states` and evidence; the engine refuses to auto-create an unknown address-keyed reserve from generic symbol defaults.

The parent imports the updated submodule normally. For optional checkpoint accrual, set `AAVE_HISTORICAL_EVIDENCE` to a JSON list of provenance-bearing observations. Required event kinds include `reserve_indices` (RAY indices and, for extrapolation, rates/validity), and `debt_mode` when cached borrower snapshots lack a verified mode. Failure on missing evidence is intentional; no available-history claim is inferred from the environment variable.

A fully specified simulation profile can carry `reserve_states`, `initial_position`, `contract_evidence`, `emode_categories`, `configuration_provenance`, `coverage_manifest`, and `require_verified_history`. See `tests/test_remaining_audit.py:test_verified_input_smoke_preserves_global_totals` for a **synthetic** example, and `simulator/evidence_loader.py` for field requirements. `protocol_parameters` evidence supplies version/sentinel coverage; reserve parameters and oracle prices have explicit validity intervals. Category histories use `emode_categories` observations. Coverage flags are source declarations, not independent on-chain certification.

Complete bundles use `TransactionBundle` or `Flashloan`, a transaction hash, source, `complete`, and log-ordered `operations`. Flash assets require explicit mode, amount, premium and protocol premium. This interface must receive decoded complete execution evidence; the raw indexed flash CSV is insufficient. Optional `ObservedLiquidation` requires receipt provenance, explicit legs and an earlier timestamp than `counterfactual_start_timestamp`.

No old cache was moved or deleted. Source/registry identity changes invalidate future simulation caches; new recommendation generation still requires a fresh run namespace. No full recommendation refresh, R execution, manuscript edit, journal communication or publication was performed. Next historical validation needs the missing state/receipt coverage and explicit address/funding migration, rather than another run presented as fully verified using the same incomplete inputs.
